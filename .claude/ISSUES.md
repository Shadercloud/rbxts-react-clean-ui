# Issues

Design/spec-vs-implementation inconsistencies and likely bugs found while back-propagating the component specifications under `.claude/specifications/components/` from the existing `src/Components/` source (2026-08-25). Each entry names the affected component, what's inconsistent, and where it's documented as current (not intended) behavior in the spec. Check items off as they're resolved; when a fix changes the intended behavior, update the corresponding spec file in the same change.

## Input

- [ ] **Select** — `Select.Option`'s `BackgroundColor3` prop is accepted but never applied; the rendered background always comes from `ColorHelper.getIntentColors(...)`. Contradicts `docs/content/docs/components/form/select.mdx`, which shows `BackgroundColor3` as a working customization. See `.claude/specifications/components/input/select.md`.
- [ ] **Button** — `fontWeight` prop is declared on `ButtonProps` but never read anywhere. See `.claude/specifications/components/input/button.md`.
- [ ] **Button** — doesn't use the shared `HoverButton` primitive; rolls its own `MouseEnter`/`MouseLeave` state instead, despite the general convention (`.claude/specifications/components/index.md`) that hover-aware controls should. See `.claude/specifications/components/input/button.md`.
- [ ] **Checkbox** — mixes two independent intent-theming systems: background color/transparency come from `theme.components.button` keyed by the generic `intent` prop, while border/icon colors come from `theme.components.checkbox.intents` keyed by `intent-checked`/`intent-unchecked`. See `.claude/specifications/components/input/checkbox.md`.
- [ ] **Checkbox** — `theme.components.checkbox.borderColor`/`.borderThickness` are declared in `src/Theme/theme.template.ts` but never read; the component sources those visuals elsewhere. See `.claude/specifications/components/input/checkbox.md`.
- [ ] **Checkbox** — `onChange` fires once on mount (its effect runs with the initial `checked` value immediately), not only on user-driven toggles. See `.claude/specifications/components/input/checkbox.md`.
- [ ] **Slider** — inherits `ContainerProps.group` but never reads it (builds its root frame by hand instead of through `Container`), so `group` is inert. See `.claude/specifications/components/input/slider.md`.

## Layout

- [ ] **Container** — the `group`-derived default width only has a visible effect when the consumer also supplies an explicit `AutomaticSize` that excludes `X` (e.g. `"None"`/`"Y"`); otherwise the default `AutomaticSize: XY` (used whenever `width`/`height` are both omitted) overrides the pixel width on the `X` axis, making `group` sizing silently inert in the common case. See `.claude/specifications/components/layout/container.md`.
- [ ] **FlexItem** — combining `group: true` (inherited via `Container`) with `FlexItem` likely breaks flex behavior: `Container` wraps `children` in `Group.Element` when `group` is set, which would move `FlexItem`'s `UIFlexItem`/`UIListLayout` onto `Group.Element`'s inner measurement frame instead of the outer frame actually placed inside the parent's `UIListLayout`, very likely making `mode`/`GrowRatio`/`ShrinkRatio` stop working. See `.claude/specifications/components/layout/flexitem.md`.
- [ ] **HStack / VStack** — for the same `spacing` value, `HStack` applies `ceil(padding / 2)` pixels between children while `VStack` applies the full padding value — likely an unintentional asymmetry rather than a deliberate design choice. See `.claude/specifications/components/layout/hstack.md` and `layout/vstack.md`.
- [ ] **Draggable** — the `React.forwardRef<Frame, ...>` ref parameter is never attached to any rendered instance, so a consumer's ref is silently dropped. See `.claude/specifications/components/layout/draggable.md`.
- [ ] **Draggable** — the `Placeholder`'s theme-driven `backgroundTransparency` is immediately overridden by a hard-coded `BackgroundTransparency={0.3}` at the call site, so `theme.components.draggable.placeholder.backgroundTransparency` currently has no visible effect. See `.claude/specifications/components/layout/draggable.md`.
- [ ] **Draggable / Droppable** — drop-target detection notifies **every** overlapping registered `Droppable` at the pointer position via `onDrop`, but the single `DroppableRegistration` reported back through `Draggable`'s `onDragged`/`onDropped` is whichever was processed last (lowest `ZIndex`), not necessarily the top-most visual match — an asymmetry between "many `onDrop` calls" and "one reported registration" that doesn't implement clean top-most-wins semantics. See `.claude/specifications/components/layout/draggable.md` and `layout/droppable.md`.
- [ ] **Fieldset** — `FieldsetContextValue.disabled` is threaded through context but read by nothing (`Fieldset.Label`, `Fieldset.Control`, `Checkbox`, `Input`, `Select` all ignore it) — setting `disabled` currently has zero observable effect. See `.claude/specifications/components/layout/fieldset.md`.
- [ ] **Tabs** — several theme fields declared in `theme.template.ts` are dead: top-level `theme.components.tabs.cornerRadius`/`.backgroundColor`, `tabs.list.borderColor`/`.borderThickness`, and `tabs.button.borderThickness` are never read (the list/content panel reuse `tabs.list.cornerRadius` instead). See `.claude/specifications/components/layout/tabs.md`.
- [ ] **Tabs** — has no controlled `value`/`onValueChange` API (uncontrolled-only), unlike `Accordion`'s equivalent controlled/uncontrolled support. Documented as an intentional API difference for now, but worth a deliberate decision rather than an unexamined gap. See `.claude/specifications/components/layout/tabs.md`.

## Navigation / Surface / Chart

- [ ] **Menu** — `MenuItem` extends `ButtonProps` and its `.mdx` doc claims `intent` and "all other Button props" are supported, but the JSX only forwards `title`, `icon`, and `Event` to the underlying `Button` — `intent` and everything else is silently dropped. See `.claude/specifications/components/navigation/menu.md`.
- [ ] **Pie** — the hide-labels prop is read as `props['Label-hidden']` (capitalized), while docs and convention suggest `label-hidden` (lowercase) — the documented lowercase prop has no effect. See `.claude/specifications/components/chart/pie.md`.
- [ ] **Pie** — no zero-total-value guard: if all values are `0` or the data array is empty, `value / totalValue` divides by zero, producing `NaN` proportions with undefined rendering behavior. See `.claude/specifications/components/chart/pie.md`.
- [ ] **Pie** — `PieProps`/`PieValue`/`PieLabel` are not exported, despite `PieProps` being the component's public prop surface and `chart/index.md` calling for chart-specific public-API interfaces to be exported. See `.claude/specifications/components/chart/pie.md`.
- [ ] **Pie / Icon** — dead theme fields: `theme.components.charts.pie.hoverDarken` is declared but `Pie` hard-codes a `0.2` default via its own `hover-darken` prop instead; `theme.components.box.intents`, `theme.components.tooltip.cornerRadius` (Tooltip actually uses `theme.components.button.cornerRadius`), `theme.components.toast.body.typography`, and `theme.components.card.borderThickness` (Card header/footer hard-code `Thickness={1}`) are similarly declared but never read. See `.claude/specifications/components/chart/pie.md`, `interaction/tooltip.md`, `interaction/toast.md`, `surface/box.md`, `surface/card.md`.
- [ ] **Icon** — `SpinningIcon`'s tween-start effect has no dependency array, so `setGoal(360); tween.start()` re-runs on every render rather than once at mount. Likely harmless since the animation loops forever, but worth confirming against `useTween`'s intended usage. See `.claude/specifications/components/surface/icon.md`.
- [ ] **Toast** — `dismiss()`/`dismissAll()` skip the fade-out animation; only self-triggered dismissal (timeout expiry or the close button) fades out. This looks intentional but is easy to mistake for an inconsistency — worth confirming it's deliberate. See `.claude/specifications/components/interaction/toast.md`.

## Resolved

- [x] **Input/Fieldset** — `src/Components/Input/Fieldset.tsx` was a byte-for-byte duplicate of `src/Components/Layout/Fieldset.tsx`, never exported from the `Input` barrel and unreachable from the public API. Removed 2026-08-25; `Layout/Fieldset` is the sole `Fieldset` implementation going forward.
