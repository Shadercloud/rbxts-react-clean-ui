# Box

`Box` is a themed container surface: background, inner border, corner radius, shadow, and padding, wrapped around arbitrary children. It follows the shared conventions in [Components](../index.md).

## Public API

- `BoxProps` composes `SpacedElementProps`, `ShadowElementProps`, `BackgroundElementProps`, `ZIndexElementProps`, `SizeElementProps`, `PositionElementProps`, and `React.InstanceProps<ImageLabel>`, plus three Box-specific fields: `'border-thickness'?: number`, `'border-color'?: Color3`, and `'background-image'?: CssBackgroundImage`.
- `Box` forwards a ref to the underlying `ImageLabel` — `Box` is a thin wrapper around [`Container`](../layout/container.md), which always renders an `ImageLabel` as its root instance (rather than conditionally choosing between `Frame`/`ImageLabel`), so every ref that terminates at `Box`'s own instance is typed `ImageLabel`, not `Frame`. This is a breaking type change for any existing `React.useRef<Frame>()`/`InstanceProps<Frame>` typed against a `Box` ref.

## Behavior

- Size defaults to `UDim2.fromScale(1, 1)` when none of `Size`, `width`, or `height` is supplied (via `SizeHelper.GetSize`); `AutomaticSize` is always set to `XY` regardless of the resolved base size.
- `BackgroundColor3`/`BackgroundTransparency` fall back to `theme.components.box.backgroundColor`/`backgroundTransparency` when not supplied as props.
- An inner `uistroke` always renders, using `'border-thickness'`/`'border-color'` props, falling back to `theme.components.box.borderThickness`/`borderColor`.
- A `BoxShadow` decorator applies `theme.components.box.boxShadow`; when that theme value is `undefined`, no shadow renders (the shadow prop-level overrides on `ShadowElementProps` still take precedence when supplied).
- A `Padding` decorator applies any of the standard padding props.
- A `Corners` decorator applies `theme.components.box.cornerRadius`.
- `props['background-image']`, falling back to `theme.components.box.backgroundImage`, is passed straight through as `Container`'s own `backgroundImage` prop, so `Container` (an `ImageLabel`) renders it directly as its own `Image`/`ImageColor3`/`ImageTransparency`/`ScaleType`/`SliceCenter`, composited underneath `BackgroundColor3` in the same way a plain background color renders — there is no separate image layer/child instance for it (unlike `BoxShadow`/`Corners`/`Padding`, which remain ordinary decorator children). It still visually composites with the solid `BackgroundColor3` fill, border stroke, corner radius, and shadow rather than replacing any of them, and sits below `children` in draw order.

## Theme

Box defaults live under `theme.components.box`: `backgroundColor`, `backgroundTransparency`, `borderColor`, `borderThickness`, `cornerRadius`, optional `spacing`, optional `padding`, optional `boxShadow`, and optional `backgroundImage`. The theme shape also declares an `intents` field (per-intent color schemes), but `Box` itself never reads it — no intent resolution happens inside `Box`; components built on top of `Box` (e.g. `Card`, `Toast`) apply their own intent colors as explicit `BackgroundColor3`/`border-color` overrides instead. Treat `theme.components.box.intents` as currently unused by `Box`.

### `padding` / `spacing`

`Box`'s inner padding resolves through the shared tiered [padding resolution](../index.md#padding-resolution): `theme.components.box.spacing` (tier 2, a `ScaleSizeValue<number>`) overrides the global spacing map per scale key, and `theme.components.box.padding` (tier 3, type `ScaledCssPadding` — either a plain `CssPadding`/`CssQuad` shorthand applying regardless of scale key, or a scale-key-indexed map of quads) overrides tiers 1/2 at the active scale key, parsed via `CssHelper.parseCssQuad` into independent top/right/bottom/left pixel offsets. A prop-level override (`spacing`, `top`/`bottom`/`left`/`right`, `padding`, `resolvedPadding`) merges **per side** against these theme tiers rather than discarding them wholesale — setting only `top` on an instance still lets `bottom`/`left`/`right` fall through to `box.spacing`/`box.padding`/the global scale. Both `box.spacing` and `box.padding` are optional and left unset in `default`/`dark`/`sandstone` — none of the built-in themes give `Box` a fixed spacing/padding override by default, so `Box`'s padding falls through to the global `theme.default.spacing`/`theme.spacing` scale-token system on every side unless a theme author or caller sets one of these.

### `backgroundImage`

`theme.components.box.backgroundImage` (type `CssBackgroundImage`, declared in `src/Theme/theme.style.ts`) lets a theme author layer a (typically 9-sliced) image — e.g. a wooden-frame or beveled-panel texture — onto every `Box` in that theme, on top of the plain background/border/corner/shadow styling. The `'background-image'` prop on `BoxProps` overrides this theme value per-instance when supplied, the same `??` prop-overrides-theme pattern used for `border-thickness`/`border-color` and `BackgroundColor3`/`BackgroundTransparency` elsewhere in `Box`. It is optional; when unset, `Box` renders exactly as it did before this field existed.

- `image` (`string | number`, required): either a raw asset id number (e.g. `123456789`, formatted as `` `rbxassetid://${image}` ``) or a full string reference (`rbxassetid://...`, `rbxasset://...`, etc, for other content sources) — passed through unchanged.
- `slice` (optional, type `CssSliceInset`, declared in `src/Interfaces/css.types.ts`): the absolute pixel coordinates of the center region's top-left and bottom-right corners within the source image, i.e. exactly Roblox's own `SliceCenter`/`Rect.new(minX, minY, maxX, maxY)` arguments — not a CSS `border-image-slice`-style edge inset. Two forms are accepted: `"A B"` (symmetric square corners — `Rect(A, A, B, B)`, e.g. `"12 288"` means top-left corner `(12, 12)` and bottom-right corner `(288, 288)`) or `"A B C D"` (direct passthrough as `Rect(A, B, C, D)`). There is no single-value form — a lone number can't be turned into two corner points without knowing the image's pixel dimensions. Any `%`/`px` unit suffix on a value is ignored; every number is treated as a raw pixel count regardless of what unit (if any) was written — there is no percentage support. When provided, the image renders with `Enum.ScaleType.Slice`. When `slice` is omitted, the image renders as a single (non-9-sliced) layer.
- `size` (optional, `Enum.ScaleType | "Stretch" | "Slice" | "Tile" | "Fit" | "Crop" | Binding<Enum.ScaleType>`, default `Enum.ScaleType.Stretch`, ignored when `slice` is set): the `ScaleType` applied to `Container`'s own `ImageLabel`, passed straight through to the native `ScaleType` prop (same enum-or-string-literal-or-binding convention used elsewhere in this package, e.g. `HStack`'s `valign`).
- `transparency` (optional): maps to `ImageTransparency`.
- `tintColor` (optional): maps to `ImageColor3`.
- `tileSize` (optional, `CssDual`): a CSS `background-size`-style 1-or-2-value shorthand (`"25%"` or `"25% 25%"` for independent X/Y), parsed via `CssHelper.parseCssDual` into a full `UDim2` (both Scale and Offset are preserved, unlike `slice`'s pixel-only insets, since tile sizes are commonly expressed as a Scale percentage). Maps to `TileSize`. Only has an effect when `size` resolves to `Enum.ScaleType.Tile`; ignored when `slice` is set (`slice` always forces `Enum.ScaleType.Slice`).
- `sliceScale` (optional, `number`, default `1`): maps directly to `ImageLabel.SliceScale`. Only takes effect when `slice` is set. `slice`'s coordinates are always in the source image's own pixel space, so a source image with a naturally large border region (e.g. a few hundred px) would otherwise always render that same large thickness regardless of how small the destination `Box` actually is; `sliceScale` decouples "which region of the source image is the border" (`slice`) from "how thick that border renders on screen", letting the rendered border be scaled down/up independent of the slice region's literal pixel size.

`CssHelper.resolveBackgroundImage(value: CssBackgroundImage | undefined)` is the shared pure function that turns a `CssBackgroundImage` into the resolved `Image`/`ImageColor3`/`ImageTransparency`/`ScaleType`/`SliceCenter`/`SliceScale`/`TileSize` prop values; it lives in `src/Helpers/css.helper.ts` alongside `parseCssSliceInset`/`parseCssDual`/`parseCssShadow`/`parseCssSize`, and is shared by any component that renders a `CssBackgroundImage` (currently just [`Container`](../layout/container.md), which `Box` composes).
